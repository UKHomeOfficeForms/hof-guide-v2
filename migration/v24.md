# Version 24

## Purpose

This page summarises important v24 considerations.

## Key concepts

HOF v24 includes a breaking change: old built-in email functionality and the `nodemailer` dependency were removed.

Services must provide and maintain their own email implementation, usually with GOV.UK Notify.

## Usage guidance

Before upgrading to v24:

- search for old emailer usage
- replace it with a service-owned behaviour
- confirm Notify templates and API keys
- test successful and failed email paths

## Examples

Service-owned Notify behaviour:

```js
'use strict';

const notify = require('hof').components.notify;

module.exports = notify({
  notifyApiKey: process.env.NOTIFY_API_KEY,
  notifyTemplate: process.env.NOTIFY_TEMPLATE_ID,
  recipient: 'email-address',
  subject: 'Application received',
  template: require.resolve('../emails/application-received.txt')
});
```

Use on final step:

```js
const sendEmail = require('../../behaviours/send-email');

module.exports = {
  steps: {
    '/confirm': {
      behaviours: [sendEmail, 'complete'],
      next: '/confirmation'
    },
    '/confirmation': {}
  }
};
```

## Common issues

### Confusing removed emailer with Notify component

The old nodemailer-based built-in email functionality was removed. The Notify component remains available but must be configured and owned by the service.

### Missing Notify template personalisation

The Notify component sends `email-subject` and `email-body` personalisation values. Ensure the Notify template expects those variables.
